# Rine: архитектура

Сервер Minecraft Java Edition 26.3 (протокол 777) на Rust. Снаружи клиент видит ванильный сервер, внутри другая модель исполнения.

## Главные решения

1. **Кодируем один раз, рассылаем всем.** Всё, что видят несколько игроков (чанки, движение сущностей, смена блоков, взрывы), кодируется и сжимается в `Frame` один раз. Каждому зрителю уходит клон `Bytes` (это счётчик ссылок, не копия). Порог сжатия общий на сервер, поэтому кадр подходит любому сокету. Шифрование потоковое и делается в задаче записи конкретного соединения.
2. **Сеть не трогает тик.** Handshake, status, login, configuration целиком идут в tokio-задаче соединения. В игровой поток соединение попадает уже в состоянии play. Входящие пакеты разбираются в tokio-задаче в `Inbound`-события и кладутся в очередь игрока.
3. **Один flush на тик.** Пакеты игрока копятся в его буфере за тик и уходят одной записью в сокет. Тысяча игроков означает тысячу системных вызовов за тик, а не сотни тысяч.
4. **Тик по фазам с параллелизмом по данным (rayon):**
   1. разбор очередей входящих событий;
   2. применение действий игроков (движение, блоки, инвентарь);
   3. симуляция сущностей в SoA-массивах (предметы, TNT, падающие блоки) параллельно;
   4. взрывы пачкой: все взрывы тика считаются параллельно по снимку мира, затем изменения сливаются и применяются, по секциям уходит один `section_blocks_update`;
   5. трекинг и рассылка: по каждому игроку параллельно, через пространственную сетку;
   6. стриминг чанков: генерация, загрузка и кодирование на пуле воркеров, тик только получает готовое;
   7. flush.
5. **Чанки хранятся плоско.** Секция держит `[u16; 4096]` со state id (O(1) get/set без палитры). Палитра строится только при сетевом кодировании и сохранении, на воркере. Закодированный пакет чанка кэшируется и сбрасывается при изменении.
6. **Генератор без зависимостей между чанками.** Деревья и прочие структуры чанк считает сам, заглядывая в детерминированные позиции соседей, поэтому любой чанк генерируется параллельно и независимо.
7. **Плагины вне тика.** JVM встраивается через JNI. События уходят в поток плагинов пачками. Синхронно (с возможностью отмены) вызываются только те типы событий, на которые плагин подписан: если подписчиков нет, цена ноль.

## Крейты

- `rine-protocol`: VarInt, буферы, NBT, кадры и сжатие, id пакетов, текст.
- `rine-data`: сгенерированные таблицы из ванильного jar (состояния блоков, предметы, сущности, реестры, теги).
- `rine-world`: секции, чанки, кодирование чанка в пакет, свет, генератор, сохранение.
- `rine-server`: сеть (tokio), игровой цикл, игроки, сущности, команды.
- `rine-plugin`: мост к JVM (фича `jvm`).
- `rine-testbot`: headless-клиент для проверки и нагрузочных тестов.

## Источники истины

- Форматы пакетов: `docs/spec/*.md`, извлечены из исходников 26.3 (`Paper-26.3/paper-server/src/minecraft/java`).
- Id пакетов: `vanilla-data/generated/reports/packets.json`.
- Данные блоков и предметов: `vanilla-data/dump/*.json` (дампер `tools/datadump`) и `vanilla-data/generated/reports/blocks.json`, `registries.json`.
